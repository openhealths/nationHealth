## Нотатки БА: джерело й можлива розбіжність

BA01 потребує перевірки семантики одиниці. [3.10.2.7.2](/Users/mefizz/Documents/Codex/ohealth/docs/technical-requirements/edition-39.json:5573), с.122, визначає quantity.value як «кількістю медичних або реабілітаційних послуг», а [3.10.2.2.2](/Users/mefizz/Documents/Codex/ohealth/docs/technical-requirements/edition-39.json:5447), с.120, вимагає одиницю з SERVICE_UNIT. Сам текст про кількість послуг не доводить, що хвилини заборонені. Для вашого правила перевіряються MINUTE, збереження, підписання, remaining_quantity та погашення: зміна напису поля сама по собі не доводить правильності тривалості. Остаточний результат буде за CP/R тестами; помилкою вашої вимоги це не оголошується.

BA02 — підтверджена вами бізнес-вимога. Формулу 5 + окремі оформлені направлення − створені призначення не встановлено у перевірених пунктах 3.10.2/3.17. Вона не підміняє remaining_quantity окремого призначення за [3.17.1.4.3](/Users/mefizz/Documents/Codex/ohealth/docs/technical-requirements/edition-39.json:6821). Відсутність цієї формули в переглянутому тексті не означає, що вона заборонена або зайва.

BA03–BA09 залишаються авторизованим продуктовим scope. Конкретна кількість кнопок, дві підвкладки й розташування документів не оголошуються буквальними вимогами ТВ без відповідного пункту. Водночас доступи, справжні статуси, API-контракти та одиниці виконуються за своїми нормативними правилами.

Уточнення про три точки відображення враховано: взаємодія, картка пацієнта, наявна частина бокового меню. Не вимагається довільно додавати п’ять окремих бокових меню; порівнюється узгодженість наявних екранів за [acceptance-матрицею](UI-SURFACES-TV39.md).

## Що ще перевіряється

Власники модулів звіряють додані guards із ТВ/API/user scope. Окремо перевіряється межа end_date працівника: заборона вже у день завершення не називається підтвердженим дефектом без визначення семантики дати в офіційному контракті. Будь-яка пропозиція прибрати правило повинна мати конкретний сценарій, код і джерело; припущення не стануть підставою для послаблення policy.

Остаточний звіт доповнюється SHA, PR і positive/negative результатом для кожного X-ID після завершення інтеграції. Основний звіт закриття: [REPORT-TV39-CLOSURE.md](/Users/mefizz/Documents/Codex/ohealth/.worktrees/i1201_tv39_clinical_umbrella/docs/tv39-remediation/REPORT-TV39-CLOSURE.md:1).
