# TV39 prescription remediation — issue #1203

Approved edition 39 only; baseline upstream/main 3ae4e34e.

## Implementation plan

1. Validate native MedicationRequest, MedicationRequestRequest, drug, qualification, dispensing and printout API contracts before consuming results. Preserve exact native detail for KEP; validate pagination before continuing.
2. Apply the same complete-course, all-package, dose-conversion, program-period and notification rules in standalone and care-plan prescription workflows, with server-side revalidation before creation.
3. Implement patient detail pages and durable draft reopening, signing/rejection/printing, all documented registry filters and full-page import, including external care-plan requests.
4. Render all dispensing records, guard SMS eligibility and explicit confirmation, and expose the verified National Price Catalogue link after signed prescription creation.
5. Exercise malformed contracts, form boundaries, patient/author authorization without side effects, draft lifecycle and pagination in the dedicated tv39_1203 database.

## Official contract sources and acceptance boundaries

Response schemas are a compact checked-in extraction from the official General MIS OpenAPI archive: preprod 9.15.9 (`openapi/preprod/general-mis.json`) and the price-link operation from demo 9.15.12 (`openapi/demo/general-mis.json`). They retain the provider's declared field types, required fields, alternatives and additional-field rules. Official descriptions that do not declare a JSON-schema format are not presented as newly declared provider constraints. No synthetic signing seed, successful status, printout URL or dispensing entry is manufactured.

The unsigned rejection contract is **PATCH `/api/medication_request_requests/{id}/actions/reject`**. Its official success example echoes `NEW`; after validating the successful exact-ID response, the local draft becomes rejected. The endpoint is not DELETE. Unconfirmed/failed responses never advance local lifecycle state.

The exact prescription price-link endpoint **GET `/api/persons/{person_id}/medication_requests/{medication_requests_id}/price_catalog_link`** exists in the official demo 9.15.12 archive and is absent from the archived preprod 9.15.9 specification. Consequently its deployed preprod availability remains unverified. The UI also provides the independently verified public catalogue, `https://ecatalog.moz.gov.ua/`, announced by the State Expert Center on 5 January 2026 and updated 18 February 2026: `https://www.dec.gov.ua/news/zapraczyuvav-vebsajt-naczionalnogo-katalogu-czin-na-likarski-zasoby/`. It never substitutes an invented prescription-specific link after an endpoint error.

Real KEP, real SMS and live ESOZ clinical writes require user-assisted acceptance; automated verification uses HTTP fakes and isolated SQL storage. These operations and manual browser acceptance were not performed by the agent, so code/test closure is separate from live operational acceptance. Shared G01 contracts outside MedicationRequest remain owned by the umbrella follow-up.
