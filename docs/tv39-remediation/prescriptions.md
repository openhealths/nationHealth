# TV39 prescription remediation — issue #1203

Approved edition 39 only; rebased integration includes upstream/main ea188869 (canonical document routes).

## Implementation plan

1. Validate native MedicationRequest, MedicationRequestRequest, drug, qualification, dispensing and printout API contracts before consuming results. Preserve exact native detail for KEP; validate pagination before continuing.
2. Apply the same complete-course, all-package, dose-conversion, program-period and notification rules in standalone and care-plan prescription workflows, with server-side revalidation before creation.
3. Implement patient detail pages and durable draft reopening, signing/rejection/printing, all documented registry filters and full-page import, including external care-plan requests.
4. Render all dispensing records, guard SMS eligibility and explicit confirmation, and expose the verified National Price Catalogue link after signed prescription creation.
5. Exercise malformed contracts, form boundaries, patient/author authorization without side effects, draft lifecycle and pagination in the dedicated tv39_1203 database.

## Official contract sources and acceptance boundaries

Response schemas are a compact checked-in extraction from the official General MIS OpenAPI archive: preprod 9.15.9 (`openapi/preprod/general-mis.json`) and the price-link operation from demo 9.15.12 (`openapi/demo/general-mis.json`). They retain the provider's declared field types, required fields, alternatives and additional-field rules. Official descriptions that do not declare a JSON-schema format are not presented as newly declared provider constraints. No synthetic signing seed, successful status, printout URL or dispensing entry is manufactured.

The unsigned rejection contract is **PATCH `/api/medication_request_requests/{id}/actions/reject`**. Its official success example echoes `NEW`; after validating the successful exact-ID response, the local draft becomes rejected. The endpoint is not DELETE. Unconfirmed/failed responses never advance local lifecycle state.

The exact prescription price-link endpoint **GET `/api/persons/{person_id}/medication_requests/{medication_requests_id}/price_catalog_link`** exists in the official demo 9.15.12 archive and is absent from the archived preprod 9.15.9 specification. Consequently its deployed preprod availability remains unverified. The UI also provides the independently verified public catalogue, `https://ecatalog.moz.gov.ua/`, announced by the State Expert Center on 5 January 2026 and updated 18 February 2026: `https://www.dec.gov.ua/news/zapraczyuvav-vebsajt-naczionalnogo-katalogu-czin-na-likarski-zasoby/`. It never substitutes an invented prescription-specific link after an endpoint error.

Real KEP, real SMS and live ESOZ clinical writes require user-assisted acceptance; automated verification uses HTTP fakes and isolated SQL storage. These operations and manual browser acceptance were not performed by the agent, so code/test closure is separate from live operational acceptance. Shared G01 contracts are coordinated prerequisites; their cross-module acceptance remains owned by the umbrella.

## Integration regression follow-up

Care-plan synchronization captures linked unsigned requests before importing prescription rows. This prevents a newly imported MR from hiding the original MRR with the same request number. Confirmed MR state takes precedence over an outdated unsigned verdict; imported local statuses use the existing enum while the native signing data is preserved. The actual `CarePlanShowActionsTest` regression checks separate IDs, signed request, active link, completed prescription and rejected unsigned request (**1 test / 8 assertions**).

The complete official MedicalProgram list exposes prescribing rules in `medical_program_settings`, while the detail DTO exposes `settings`. All prescribing form, signing and SMS readers now use both documented shapes consistently, including an optional absent program. The resolved default program is persisted in the durable form as well as the submitted payload, so later activity/qualification checks use the same identity. Tests cover maximum period, notification-disabled behavior, null program and the default-program persistence path.

Legacy external list caches classified unsigned requests as prescriptions. Reclassification is limited to an unsynchronized external cache and requires a complete validated unsigned detail with the exact stored ID and patient. Local drafts, synchronized records, reverse changes, foreign patients and malformed native data are rejected without database changes. The storage regression imports an accepted cache twice and verifies identifier/dosage stability.

Broader patient registry and standalone signing fixtures now use complete official native response contracts, explicit catalog isolation and current authorization conventions. Actual API validation remains active; search denial uses translated flash feedback and leaves the registry empty. The care-plan synchronization concern imports its resource discriminator explicitly.

An earlier umbrella integration checkpoint passed **197 tests / 870 assertions** in `tv39_shared`; the final owned-branch verification above supersedes its prescription result. That historical run does not certify the current umbrella or live ESOZ behavior.

The pharmacy `MedicationDispenseLifecycleService` is outside these physician/assistant prescribing workstations: its sole UI consumer is `MedicationRequestIndex` at the separate pharmacy route, requiring `medication_request:details_pharm` or `medication_dispense:write/process`. Physician dispensing history uses `MedicationRequestLifecycleService::getDispenseHistory`, which reads every validated `MedicationRequest::getDetails` page. Pharmacy PIS redemption was not expanded by this remediation.
